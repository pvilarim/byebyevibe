# Design — add-tooling-guidance (v1, guidance text + advisory script extension)

## Context

Explore merge `explore-tooling-guidance` (D1–D12) settled the mechanism: a normative resolution cascade for external-tool actions (override → CLI → MCP → suggest → manual), a static gap-check as the primary detector (inversion vs skills, whose signals only surface in conversation), a security-hardened offer-only suggestion sharing the skill-guidance anti-noise cap, and durable refusals. The delivery skeleton mirrors archived change `2026-08-01-add-skill-guidance`: canonical dual-surface skill, day-1 section narrated by `/opsx:help`, archive confidence question, kit templates + MANIFEST checksums, evaluation stub.

Constraints that shape this design:

- **Upstream ownership:** `/opsx:*` commands and `openspec-*` workflow skills are generated by OpenSpec; the kit cannot patch upstream surfaces in installed repos (no APPEND merge mode). Hub-local edits to those surfaces are accepted practice (session-coordination and skill-guidance precedents).
- **Existing foundation:** `scripts/verify-infra.sh` maintains `openspec/infra.md`; `scripts/preflight-sdd.sh` owns the Preflight section and already stamps "MCP names (advisory)"; R10 (`AGENTS.md`) already forces manifest reads before install actions; `/opsx:help` step 4 already routes install intent to `infra.md`; UI-module rows already model "status in manifest, how-to in a dedicated doc".
- **Security posture (D6):** an MCP is credentials + third-party server + prompt-injection surface, not repo text. "Never create unprompted" hardens into "never install/configure unprompted", no exceptions.
- **Non-goals (binding):** no auto-install; no always-on rule; no stack-inference; no telemetry; no durable per-tool preference; no second suggestion slot; no changes to `sdd-metrics.sh` or `preflight-sdd.sh`.

## Goals / Non-Goals

**Goals:**

- Make the cascade the agent's default resolution order for external-tool actions, anchored in R10 and taught in day-1 §8, narrated by `/opsx:help`.
- Detect tooling gaps statically via `verify-infra.sh` (report absence, not need) and conversationally via the signal catalog (secondary, paste-caveat documented).
- Suggest — never install — with the security-hardened three-part message, under the shared cap.
- Make refusals durable (`declined` in `infra.md`; commented `.env.example` key = considered-and-declined).
- Establish `doc/tooling-install.md` as the per-tool how-to home (official link + verify command + "verified on YYYY-MM").
- Ship dual-surface via `sdd-kit/templates/` + MANIFEST checksums; record the Claude Code/Cursor asymmetry.

**Non-Goals:**

- Stack-inference gap analysis, per-tool usage telemetry, durable per-tool preferences, preflight gap WARNs (v2 — recorded as deferred requirements in the `sdd-tooling-guidance` delta).
- Forking upstream OpenSpec workflow files into the kit.
- Any gate or blocking behavior — the gap-check is advisory report-only.

## Decisions

### D-A — Canonical text lives in a new kit-owned dual-surface skill `sdd-tooling-guidance`

The full corpus (cascade with the second-manual-fall trigger, CLI-first rationale + per-tool MCP exceptions, session-only override, signal catalog with paste caveat, security-hardened suggestion message verbatim, shared cap, durable-refusal check against `infra.md`, pointer to `doc/tooling-install.md`) becomes one skill shipped exactly like `sdd-skill-guidance`:

- Live: `.claude/skills/sdd-tooling-guidance/SKILL.md` + `.cursor/skills/sdd-tooling-guidance/SKILL.md`
- Kit: both mirrors under `sdd-kit/templates/`, registered in `MANIFEST.yaml` (profiles APP/DOCS_SPECS/HYBRID, merge COPY) with regenerated checksums.

Surface asymmetry (D12 research) is encoded here: the `.claude/` body MAY reference harness tools (`SearchMcpRegistry`, `ListConnectors`); the `.cursor/` body replaces that with "suggest + point to `doc/tooling-install.md`". This is the one place the mirrors intentionally diverge — both carry a note saying so.

*Alternatives considered:* (a) always-on `.cursor/rules/*.mdc` — violates the no-always-on non-goal; (b) folding into `sdd-skill-guidance` — different security posture and different primary detector would bloat one skill's triggers; (c) doc-only — gives the agent nothing to load at suggestion time.

### D-B — Cascade anchors in R10; hub apply surfaces get a compact clause

The cascade must govern the agent whenever it acts on an external tool — which happens mostly in apply, but not only. Two anchors:

1. **R10 (`AGENTS.md`)** gains one sentence: the resolution order (override → CLI → MCP → suggest → manual). R10 is already the always-read install-intent rule; extending it is cheaper and more reliable than any new rule. Spec home: `sdd-workspace-manifest` MODIFIED requirement.
2. **Hub apply surfaces** (`.claude/commands/opsx/apply.md`, `.cursor/commands/opsx-apply.md`, both `openspec-apply-change` SKILL.md mirrors) get a compact (~10-line) "Tooling cascade (CLI → MCP → manual)" section — cascade skeleton, second-manual-fall trigger, shared cap, pointer to `sdd-tooling-guidance` — same duplication pattern as the existing "Session coordination (apply)" sections.

Installed repos get the behavior via the kit-owned skill (D-A) plus their own AGENTS.md profile; hub gets both. Upstream-update clobber risk is the same accepted exposure as session coordination.

### D-C — Shared cap lands as a MODIFIED requirement on `sdd-skill-guidance`

The cap text lives in the skill-guidance spec today ("capped at one per session"); leaving it untouched while a second mechanism claims to share it would leave two specs asserting independent caps. The open question from research resolves as: amend `sdd-skill-guidance`'s cap requirement to "shared across proactive suggestion mechanisms, strongest signal wins", and have `sdd-tooling-guidance` reference it. Hub explore/propose surfaces' existing "Skill suggestion" sections gain one line noting the cap is shared with tooling suggestions.

### D-D — Durable refusals live in `infra.md` as a `declined` status value

Resolves the research open question toward the leaning: one manifest, already R10-protected, no new file. `declined` joins ✅/❌/`[NEEDS VERIFICATION]` as a valid status; agents treat it as "do not re-suggest, use remaining cascade rungs"; `verify-infra.sh` suppresses declined rows from the gap report. The commented-out `.env.example` key is the second refusal signal, honored by the same rule. Spec home: `sdd-workspace-manifest` ADDED requirement.

*Alternative considered:* dedicated `openspec/tooling-declined.md` — rejected: a second manifest splits R10's read obligation and duplicates status bookkeeping.

### D-E — Gap-check extends `verify-infra.sh` only; preflight stays untouched

Resolves the research open question ("leaning: both") to **verify-infra only in v1**: preflight already surfaces "MCP names (advisory)" and runs at phase 0, when tooling gaps are expected and a WARN is noise without action; `verify-infra.sh` is the post-install/periodic tool where the report is actionable and already writes the manifest sections the gap-check feeds. v1 scope: presence/absence of `.mcp.json` / `.cursor/mcp.json`, `PATH` availability of manifest-listed CLIs, `.env.example` key names (commented = declined), `declined`-row suppression. Advisory output — never a non-zero exit for gaps. Periodic cadence rides existing habits (the day-1 section and skill point operators at running it alongside the N=5/T=30 metrics nudge) with no change to `sdd-metrics.sh`. If v1 proves insufficient, preflight WARNs are the recorded v2 candidate.

### D-F — Day-1 doc gains §8 "Tooling — CLI → MCP → manual"; "Next step" renumbers to §9

New section between §7 Skills and the handoff example: cascade in plain language, "key → CLI → MCP unless only MCP delivers the capability", MCP permanent context cost, session override, never-install-unprompted guarantee, where install how-to lives (`doc/tooling-install.md`) and where status lives (`infra.md`). §6 "Confidence (archive)" gains the manual-work question. Renumbering: `§0–§8` → `§0–§9` in `openspec-help` SKILL.md (live ×2 + kit ×2) and `/opsx:help` commands (live ×2 + kit ×2); the help skill's section table gains the §8 row. Same priced cost as the skill-guidance renumbering.

### D-G — Suggestion message specified once, verbatim, security parts mandatory

Written once in the `sdd-tooling-guidance` skill body, referenced everywhere else. Shape:

1. **Will:** "If we configure <tool> (CLI/MCP), I can do <action> directly in future sessions instead of narrating manual steps."
2. **Won't / costs:** "I never install or configure anything myself — you run the steps. An MCP server would see <data scope>; keys live in `.env` (never committed); only official sources/trusted registries. An active MCP charges its schemas to every session — for occasional use, CLI + key is cheaper."
3. **Decide:** "Want to set it up? (yes / no / later)" — a "no" is recorded as `declined` in `infra.md` and never re-suggested.

### D-H — Per-tool how-to doc `doc/tooling-install.md` (perishability mitigated)

Mirrors `doc/design/002-ui-module-install.md`: `infra.md` rows link here; each entry is official-doc link + the command that proves it worked + "verified on YYYY-MM" marker. v1 seeds the doc with the pattern and the tools already named in `infra.md` (github-mcp-server; Figma MCP as the MCP-only exception exemplar) rather than a speculative catalog. Ships single-copy via kit templates like the day-1 doc.

### D-I — Evaluation stub + MANIFEST bookkeeping

`doc/avaliacoes/2026-08-01-tooling-guidance.md` from `TEMPLATE.md` (Decision: Adopted; cites research D1–D12), row in `doc/avaliacoes/README.md`. MANIFEST: new entries for the two skill mirrors and `doc/tooling-install.md`; refreshed `sha256` for day-1 doc, help skill/command, apply/archive surfaces, and `verify-infra.sh` templates. Gate: `bash sdd-kit/gen-manifest-checksums.sh --check`.

## Risks / Trade-offs

- [Suggestion fatigue with two mechanisms live] → shared cap (one per session across kinds), offer-only posture, static check does most detection silently.
- [Operator installs an MCP from an untrusted source or over-installs for sporadic use] → trusted-source constraint and context-cost trade-off are mandatory parts of the message; never-install-unprompted is absolute.
- [Install instructions rot] → official-link + verify-command pattern over walkthroughs; "verified on YYYY-MM" markers; `infra.md` "Verify with" column stays the source of operational truth.
- [Gap-check false positives read as nagging] → report-only output, `declined` suppression, commented-key convention, absence-not-need scope.
- [Upstream `openspec update` clobbers hub apply/archive clauses] → same accepted exposure as session coordination; kit-owned skill keeps guidance reachable; re-apply after updates.
- [`verify-infra.sh` regression breaks existing manifest stamping] → extension is additive output; existing marker ownership untouched (Preflight section remains preflight's); gate tasks include a clean run.

## Migration Plan

Additive change: new files, appended sections, additive script output. No gate, hook, or CI behavior change (`sdd-gates` unaffected; gap-check never fails the script for gaps). Deploy = merge; rollback = revert commit. Checksums regenerated before commit.

## Open Questions

None blocking v1. Research open questions resolved here: durable-refusal location → `infra.md` `declined` status (D-D); shared cap → MODIFIED `sdd-skill-guidance` requirement (D-C); gap-check delivery → `verify-infra.sh` only, preflight WARNs recorded as v2 candidate (D-E). Deferred to v2: stack-inference, per-tool preference column, usage telemetry (Cursor degradation problem inherited), preflight gap WARNs.
