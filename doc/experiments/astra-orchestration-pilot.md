# Astra orchestration pilot

Experimental and optional. This hub package prepares a protocol; it implements no runtime and reports no measured trials, model superiority or adoption decision. Execution belongs to a separately approved APP consumer change. OpenSpec remains the authority; evidence receipts and any dashboard are projections of that authority.

Sources: [consolidated research](../../openspec/changes/evaluate-astra-orchestration-readiness/research.md), [pilot design](../../openspec/changes/add-astra-orchestration-pilot/design.md), [project constitution](../../openspec/project.md). Existing [handoff](../../openspec/specs/sdd-session-handoff/spec.md), [coordination](../../openspec/specs/sdd-session-coordination/spec.md), [task patterns](../../openspec/specs/sdd-task-patterns/spec.md), [tooling guidance](../../openspec/specs/sdd-tooling-guidance/spec.md), [issue traceability](../../openspec/specs/sdd-issue-traceability/spec.md), [metrics](../../openspec/specs/sdd-metrics/spec.md), [install kit](../../openspec/specs/sdd-install-kit/spec.md), [install narrative](../../openspec/specs/sdd-install-narrative/spec.md) and [CI gates](../../openspec/specs/sdd-ci-gates/spec.md) remain authoritative.

## Trial admission

Complete the [registration](templates/astra-pilot-registration.md) before any assessment or trial. Missing required inputs mean **NOT READY**, not permission to select convenient defaults. Record repository/worktree/base commit and dirty-content fingerprints; reviewed consumer change; demand and independent acceptance commands/rubric; reviewer/integration owner; host/version, model identifiers and settings; verified tools and index coverage; authorization identifying approver, action/scope and artifact revision; numeric spend or credit ceiling and unit, elapsed-time limit, retry limit, and concurrency limit. Initially allow at most two active workers, one writer per worktree, with no uncontrolled nested fan-out.

Local Codex with Astra is an initial host hypothesis, not a dependency or a claim of available capabilities. Verify actual model access/settings, separate phase chats, required Bash/scripts and worktree-lock behavior on the selected OS. Record necessary external capabilities individually; Cursor, Codex, API adapters, GitHub and particular knowledge-tool hosts are not newly mandatory platform dependencies. Preserve existing mandatory consultations through the permitted evidence paths below. Model ability alone does not provide scheduling, persistence, tools or approval.

Name the person or host control enforcing each limit and cite its verification. Without an enforceable numeric cost/credit ceiling, no trial, including F, is admitted. Missing tokens allows functional testing only with an enforceable alternative budget; missing comparable costs prevents economic conclusions. Do not fabricate a ceiling, threshold or usage value. Stop at registered limits; extending a limit requires an explicit new decision recorded before affected work resumes.

H1 assessment has its own approved scope, budget and restricted input packet. The evaluator privately freezes the reference rubric/map revision before assessment; provide only demand and applicable source constraints to the coordinator. Do not put this full protocol, the evaluator fixture below, reference map, research answers or decision report in H1 executor context. Capture the first decomposition with timestamp/revision before revealing the reference. The evaluator scores justified alternative solutions fairly. A leaked reference makes H1 inconclusive; retain the contaminated attempt and use a fresh equivalent fixture for another assessment. After assessment, review and authorize the execution dependency map before dependent implementation.

F admission requires implementation authorization and the reviewed dependency map. T requires a passed F for that configuration. M requires passed functional gates, a quality-valid topology comparison and recorded topology selection. A material repair or model/host substitution produces a new configuration; repeat affected functional cases before comparison and retain previous failures/costs.

## Hypotheses

For every row, register a numeric or rubric criterion before data collection, metric units, evidence oracle/revision, independent evaluator and roadmap consequence. Record observed result as not measured until executed; report supported, refuted, unsupported or inconclusive with limitations. Missing evidence is not support. An illustrative 20% time improvement in research is not a default target or promise.

| ID / claim to test | Metric and evidence oracle | Criterion to register / inconclusive path | Roadmap consequence if supported |
|---|---|---|---|
| H1 Decomposition is useful | Acceptance coverage, missed dependencies, invalid splits; timestamped first answer against evaluator-held reference | Minimum coverage and allowed errors; accept justified alternatives; leakage requires fresh fixture | Improve bounded decomposition procedure |
| H2 Parallelism improves delivery | End-to-end and active elapsed time per accepted integrated demand, spread and integrated acceptance results, B versus C | Time target plus quality tolerance; model/scope confounds or unstable sample are inconclusive | Selective parallelism only for demonstrated dependencies |
| H3 Knowledge traces are useful | Independent trace scoring: relevant source; changed or confirmed named decision; unusable; source and decision revisions | Pre-record scoring rubric/required usefulness; missing trace limits conclusion; observational, never causal | Refine query triggers and source coverage |
| H4 Artifacts support recovery | Recovery time, ownership reconciliation, duplicate effects and restored valid state versus pre-recorded fault oracle | Recovery deadline and permitted failures; unavailable oracle is inconclusive, failed recovery is a failure | Recovery work or bounded artifact recovery |
| H5 Routing improves economics | Comparable full cost per accepted integrated demand for fixed versus mixed policies, with integrated quality | Cost target and quality tolerance; missing comparable costs or zero outcomes prevents efficiency claim | Separate routing experiment/proposal |
| H6 Coordination reduces operator effort | Total preparation + scheduling + supervision + approval + corrective minutes over identical observation boundary | Total effort target with all categories visible; missing categories/comparability is inconclusive | Sequential coordination or retain manual workflow |
| H7 State is reconstructible | Independent reconstruction of phase/status, authorization, tested revision and integration state against evaluator-held evidence oracle | Register accuracy threshold and state vocabulary; unknown for absent evidence, disputed for contradictions | Instrumentation before dashboard |

For H7 pre-register phase vocabulary (explore/propose/apply/archive) separately from status (not started/running/blocked/failed/completed/unknown/disputed), with acceptance criteria for each. Archive, merge and release remain separate evidence fields. The evaluator freezes the oracle before reconstruction; the reconstructor receives evidence receipts, not the oracle. A completed label requires matching acceptance evidence, not a worker assertion.

## Comparisons

Stage F is a functional prerequisite, not an economic victory. Evaluator fixture: front A supplies a shared report/export contract, B depends on that contract for UI, and C is an independent reproducible bug. An equivalent demand may preserve these dependency/independence properties. Keep this fixture outside H1 input. Use disposable consumer trial branches, distinct writer worktrees and at most two workers. Pre-register every injection before applying it:

| Injection stimulus | Expected containment/recovery | Oracle and deadline to freeze | Failure condition |
|---|---|---|---|
| Relevant index snapshot made stale | Detect snapshot mismatch; block impact-dependent work; authorized refresh or established equivalent source evidence | Expected source revisions/callers/tests, named reviewer, numeric deadline | Unknown impact treated as zero; dependent mutation before evidence; deadline missed |
| Worker interrupted at registered checkpoint | Stop replacement writes until ownership/effects reconciled; new linked attempt restores artifact-backed state | Expected writes/effects/checkpoint, ownership evidence, numeric deadline | Active writer force-released, duplicate effect, unresolved ownership, lost state or deadline missed |
| Approved contract changed | Block dependent admission, invalidate affected approval/dependency/tests, reassess and retest available approved base | Contract/base revisions, approval coverage and combined acceptance commands, numeric deadline | Old approval/test receipt reused for changed contract; unauthorized dependent work or deadline missed |

The stimulus is not itself a failed recovery. Score the response against the oracle and deadline. Preserve failed attempts and infrastructure failures. Any authority, dependency, concurrent-write, duplicate-effect, lost recovery, false-completion, limit or integrated-validation failure stops affected work and prevents comparative admission until the repaired configuration passes affected F cases.

Stage T compares **A operator-coordinated sequential**, **B Astra-directed sequential**, **C Astra-directed parallel**. These arm letters are separate from the F fixture front letters. A versus B isolates coordination; B versus C isolates concurrency. Hold demand, base, worker models/settings, tools, acceptance rubric and reviewer protocol constant. Record operator launch/scheduling effort. Do not attribute a combined model/scope change to parallelism.

Start with three trials per configuration as exploratory screening. Before T, freeze eligibility/exclusion rules, arm order variation, equivalent reset procedure, leakage prevention, environment/cache accounting, sample-extension trigger, maximum trial count and stopping rule. Register clock start/end and observation window: end-to-end includes queue, approval, retry and integration waits; active execution is separate. Do not stop clocks selectively for difficult attempts. Show per-run values and variability; three trials do not establish statistical significance. At the sample limit unresolved instability remains inconclusive.

Only after quality-approved topology selection, stage M compares fixed worker allocation with mixed-model routing using that topology. Freeze both policies and escalation rules before M, maintaining the same scope/base/rubric and accounting boundaries. Record any deviation as a configuration change; never silently substitute models. Retain configuration resets, excluded costs, setup/F costs, comparison costs and full pilot totals.

## Authority and integration

Each phase uses a separate chat/session and the existing Session Handoff, not just a new ID in one conversation. A phase-local supervisor may schedule within authorized scope; it has no permanent cross-phase exception. If the host cannot launch separate phase sessions, the operator opens them from durable handoffs and records that effort. Do not describe manual launch as autonomous support.

Before local apply, run `bash scripts/sdd-session-register.sh --phase apply --change-id <consumer-change>` and `bash scripts/sdd-session-check.sh --phase apply --change-id <consumer-change>`; release with `bash scripts/sdd-session-release.sh` on completion/pause. Verify the host's actual lock behavior during admission; an advisory presence record alone does not prove exclusive ownership or process identity. Never force-release a live writer. Parallel writers require distinct worktrees and explicit path ownership. Index writes sharing one directory are serialized separately.

Approval survives a new attempt/session if its approver, action/scope and artifact revision remain valid. Missing/ambiguous evidence blocks affected actions; silence, receipts and dashboard labels cannot approve them. A changed scope, contract or base invalidates affected dependency/verification evidence until reassessment and fresh checks. Independent authorized work may continue if disjoint and within limits.

The designated integration owner reconciles branches in dependency order and runs affected tests on the combined revision. Individual branch success is not integrated acceptance. Serialize overlapping spec promotions under OpenSpec. Archive, merge and release require their own authorized phases/actions and evidence; a finding fixed on a branch is not thereby released. External issue/PR writes require explicit authorization; local source-backed evidence can suffice where allowed.

## Recovery

Use the [run record](templates/astra-pilot-run.md) for every attempt, including failed, interrupted and contaminated attempts. Record the following matrix fields before resuming; never replace history with temporary session JSON.

| Condition / detection evidence | Decision owner | Affected work / immediate decision | Retained evidence | Resumption criterion |
|---|---|---|---|---|
| Astra/host unavailable before admission: access probe failure | Operator | NOT READY; no trial admission | Probe, host/model/configuration and access limitation | Access/settings verified and admission approved, or separately registered/revalidated replacement |
| Astra/host lost during execution: error/time record | Operator | Stop new affected admissions; establish worker ownership | Original attempts, checkpoints, effects, budget consumed | Same configuration verified, or new configuration revalidated; never silent substitution |
| Unknown ownership/effects: interrupted writer and inconclusive source checks | Operator/worktree owner | Block replacement writes; no speculative retry or forced live-writer release | Process/lock observations plus actual files, receipts and effect reconciliation | Exclusive ownership and nonduplicated effects established from source evidence |
| Git conflict, semantic incompatibility, overlapping spec promotion: merge/test/spec evidence | Integration owner | Stop affected integration/promotion; preserve independent authorized work | Both revisions, conflict, failed combined checks | Resolve dependency order; reassess scope/contract approval; fresh combined checks and serialized promotion |
| Changed contract/base: revision mismatch | Contract approver and integration owner | Block dependents; invalidate affected approval/dependency/verification evidence | Old/new contract, approval scope, old checks and affected work list | Available approved base, reviewed dependency map and fresh affected checks |
| In-scope bug: reproducible error | Scope owner and reviewer | Record reproduction; follow R6 failing test before repair | Report, reproduction, cause, fix, regression test, integrated revision and release state | Regression and affected integrated checks pass within existing authority |
| Bug changes contract or is unrelated: scope comparison | Operator/approver | Contract change needs reassessment/handoff; unrelated bug needs separate change | Reproduction and blocked-scope reference; no unauthorized external writes | Separately approved scope and phase handoff; classify quality failure before comparison |
| Missing/ambiguous approval: no covered approver/action/revision | Human approver | Block affected actions | Exact gap and existing valid authorization | Explicit decision covering affected artifacts; retain valid approvals across attempts |
| Usage missing: provider report lacks unit/coverage | Budget owner and evaluator | No economic claim; functional testing only within enforceable alternative ceiling | Available credits/usage and coverage gaps, enforcement evidence | Verified enforceable budget for F; comparable costs required for economic assessment |
| Knowledge unavailable/stale/injected: query error or snapshot mismatch | Knowledge owner and reviewer | Follow Knowledge tools; block claims/mutations requiring unknown impact | Queries/errors, snapshot identity, direct source reads and uncovered scope | Required evidence established under existing rules; no silent waiver or installation |
| Limit reached, duplicate effect, scope breach or false completion: limit/check/authority evidence | Operator and reviewer | Stop affected trial, classify safety/correctness versus infrastructure failure | All attempts, costs, intervention and oracle mismatch | Explicit repair/authorization decision, new configuration when material, affected F cases pass |

The standard workflow remains available outside the trial. Stopping the pilot does not remove OpenSpec, gates, artifacts or optional-module choices.

## Knowledge tools

Apply the existing cascade: session operator override → configured CLI → configured MCP → offer-only configuration suggestion under the shared one-per-session cap → manual instructions. Honor durable refusals. Do not install or rebuild without authorization. Consult mandatory sources even when failure is expected; record failure, not a fabricated success.

| Trigger / state | Action and evidence | Reuse / blocking rule |
|---|---|---|
| Architecture uncertainty or type D/E research | Consult Graphify concepts and GitNexus structure; record query, repository/worktree/revision, dirty fingerprints, index ID and corpus coverage; verify cited sources | Reuse only for unchanged relevant snapshot; no unconditional type A investigation |
| Before symbol change | GitNexus impact plus actual changed symbols, callers/contracts and affected tests | Unknown blast radius blocks dependent mutation; empty degraded query is not negative evidence |
| Before commit | Required change detection and affected-flow review | A failed mandatory check is recorded; affected commit waits if evidence cannot be established |
| Coherent edits, rebase/merge or changed dependency | Invalidate affected snapshot; authorize refresh only when current downstream evidence is needed, then re-query | No rebuild per keystroke or merely for idle time; serialize shared index writers |
| Healthy index | Query relevant snapshot and verify source identity/coverage | Healthy status alone does not prove document ingestion or acceptance |
| Stale index | Record mismatch; use authorized refresh preserving coverage, then re-query, or authorized equivalent reads | Never claim no dependencies from stale results |
| Absent/broken/declined retrieval | Record attempted mandatory consultation; follow permitted equivalent codebase reads on actual revision under task patterns | List changed symbols, callers/contracts, tests and uncovered scope; no blanket waiver of D/E consultation or change detection; affected mutations/commits wait if evidence remains insufficient |
| Deliberate fault injection | Record bounded injection authorization, stimulus, expected oracle and deadline separately from ordinary degradation | Injection does not authorize implementation with unknown impact |

Graphify code-AST refresh and Markdown semantic ingestion are different operations. Verify the latter's actual corpus/configuration/cost; an AST-only green status cannot certify accepted documents. Record coverage gaps and snapshot invalidation, including dirty content, in durable evidence. Existing historical `sdd-metrics.sh` reports are proxies, not trial token/cost telemetry.

## Decision boundaries

Use the [decision report](templates/astra-pilot-decision.md). Quality and authorization gates precede efficiency: a faster unauthorized or incorrect result is rejected. Outcome unit is one accepted integrated demand. Per-configuration cost per accepted outcome equals comparable measured costs of **all eligible attempts**, including failures, retries and recovery, divided by accepted integrated demands. Zero accepted outcomes gives **undefined**, with spend/failures displayed. Missing comparable coverage makes economics inconclusive. Avoid double-counting nested usage or reasoning/output charges; include coordinator, workers, reviews, integration and tools.

After all trials, review how a definitive proposal should change based on evidence, defects, costs, interventions, capability gaps and standard-workflow compatibility. Allow no adoption, sequential coordination, selective parallelism, recovery first, routing research or instrumentation before dashboard. Choose proceed to a separate proposal, further experiment or defer; protocol completion itself supports none of these empirically.

Preserve the standard workflow for users declining Astra. Future adoption must be explicitly reversible opt-in without removing OpenSpec artifacts/gates. A routine C2 framework upgrade never authorizes Astra enablement or silent conversion of older releases. A later migration proposal must define source-version detection, supported source releases, repair, separate framework upgrade and enablement, dry-run diffs and rollback evidence. Dashboard, optional installation, migration implementation and production routing remain separately reviewed scopes. A dashboard is a read-only evidence projection unless a separate controls proposal is approved; it cannot become a source of authority.

## Consumer handoff

1. Select an APP repository and representative demand in a separate reviewed consumer change. The hub apply does not execute that demand. Keep its existing AGENTS/OpenSpec authority and optional tooling policy.
2. Create `openspec/changes/<consumer-change>/evidence/astra-pilot/<experiment-id>/` in that consumer. Copy only the three templates as `registration.md`, `run-<run-id>-attempt-<n>.md` and `decision.md`. Store evaluator-only H1/H7 references separately under evaluator control, outside executor context; do not copy this evaluator protocol into H1 input.
3. Record the hub repository locator, full commit SHA containing the reviewed protocol/templates/research, their paths and content hashes. For a published repository use revision-pinned links of the form `https://<host>/<owner>/<repo>/blob/<full-sha>/<path>`. A locally accessible immutable Git source is also valid; no GitHub host is required. Do not pin to a revision that predates the package. If the package is still uncommitted, consumer provenance/admission stays NOT READY until an accessible reviewed revision exists.
4. Replace every template `HUB_*` source placeholder and any hub-relative link with an accessible revision-pinned reference; use relative links only for consumer-owned evidence. Verify each target and fragment at that revision. Templates deliberately contain no hub-relative Markdown links; do not copy hub specs/research/history into the APP to repair links.
5. When research or the pilot change is later archived, the hub maintainer updates active relative links to the actual archive path and checks them. Existing consumer pins continue to identify the historical source at its original path/revision; new copies resolve the actual path at their selected revision. Never guess an archive date or silently repoint an old receipt to new content.
6. Complete and review registration, including restricted H1 assessment input, numeric limits and separate execution authorization. Hand off each phase into a new chat with the command, consumer change, registration/tasks/evidence paths and `openspec/infra.md` (at most about 15 lines). Release local apply sessions on pause/completion. Actual trial outcomes remain unpopulated until measured.
